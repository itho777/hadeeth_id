# Search pre-index — hadeeth.id

Built 2026-11-22. One slim, engine-ready document per hadith, derived from the
exact same row files the live site reads.

## Shape

```json
{
  "id": "native_lidwa_bukhari_1",
  "dataset": "native_lidwa",
  "book": "bukhari",
  "book_en": "Sahih al-Bukhari",
  "book_ar": "صحيح البخاري",
  "number": "1",
  "num": 1,
  "chapter_id": 1,
  "chapter": "Revelation",
  "chapter_ar": "",
  "text_ar": "حَدَّثَنَا …",
  "text_ar_norm": "حدثنا …",
  "text_id": "Telah menceritakan …",
  "text_en": "Narrated …",
  "grade": "Shahih",
  "rawis": ["Umar bin Al Khaththab bin Nufail", "…"],
  "langs": ["ar", "id", "en"],
  "url": "hadith.html?book=bukhari&id=1"
}
```

- `id` is the stable primary key. Only `[A-Za-z0-9_-]`; numbers like Fawaz's
  `402.2` get a short hash suffix so they cannot collide with `402_2`.
- `text_ar_norm` is harakat-stripped, alef/ya/ta-marbuta unified, `ﷺ` spelled
  out, Arabic-Indic digits converted. `text_ar` stays verbatim for display.
- `dataset` is `native_lidwa` or `fawazahmed`, matching the site's selector.
  A Fawaz document's `url` carries `&dataset=fawazahmed`.
- `num` is an integer for sorting; `number` is the display string.

## Commands

```bash
python scripts/build_preindex.py                    # rebuild shards + _index + _catalog
python scripts/site_r2.py upload                    # additive; prunes only bucket-only keys
python scripts/site_r2.py verify
python scripts/preindex_mirror.py --d1              # D1 registry + small shards
python scripts/preindex_mirror.py --meili           # Meilisearch, all shards
```

`preindex_mirror.py` is idempotent (`INSERT OR REPLACE` in D1, stable primary
key in Meilisearch). `build_preindex.py` merges the manifest additively — it
never regenerates it from the local tree, because the bucket holds objects
whose build inputs are no longer on disk.
